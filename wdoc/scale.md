# Scale and Keg Monitoring

The Scale page supports up to two HX711 load-cell scales connected to the same ESP32. Add a scale in Device Setup, enter a scale name and keg contents, then select the DOUT and SCK GPIO pins. The planned wiring on this build (rotary encoder disabled) is: GPIO 25 = HX711 #1 DT, GPIO 26 = HX711 #1 SCK, GPIO 27 = HX711 #2 DT, GPIO 33 = HX711 #2 SCK. Power each HX711 from 3.3 V and join all grounds. Do not use flash pins 6-11, GPIOs already assigned to BrewPiLess hardware, UART GPIO 1/3, or GPIO 34-39 as SCK. GPIO 0, 2, 5, 12 and 15 are boot-strapping pins and may affect boot depending on attached hardware.

On the Scale page, select **Use scale** to enable readings. When it is off, HX711 reads, daily measurements and scale history recording are stopped.

## Calibration

1. Leave the scale platform empty and select **Zero empty platform**. The controller averages 30 raw HX711 readings (about three seconds) and does not require the live count to freeze.
2. Place an object with a known mass on the platform, enter its mass in grams and select **Calculate factor**. The same 30-reading average is used for the scale factor.
   Both averages compare the mean of the first 15 readings with the last 15. If they differ by more than the **Stability limit** (1000 raw counts by default, set per scale on the Scale page), the load changed during averaging and nothing is saved; the page asks you to wait a moment and try again. Random noise averages out in both halves, so a still but noisy load cell passes; raise the limit if it keeps failing anyway. The result message shows the measured difference, standard deviation and spread so the limit can be tuned.
   **Calculate factor** also fails without saving if the platform has not been zeroed yet, or if the known mass barely changed the reading (at least 100 raw counts or five standard deviations above zero is required). If the HX711 stops sending readings, calibration stops after 10 seconds and the scale state shows **No signal - check HX711 wiring**. Saving settings from the Scale or Device Setup page does not change the stored zero or factor.
3. Verify the result with a second known mass.
4. Enter the empty keg mass and keg capacity separately. Platform zero and empty keg mass are different values.

The beer name and scale name are labels entered by the user; the weight sensor cannot identify the beer. Keg temperature uses the configured fridge temperature sensor.

## Daily Level and Consumption

The live weight on the Scale and main pages is the average of the last 8 readings. It is for display only and is not recorded.

Once a day at the **Daily measurement time** (08:00 by default, set on the Scale page), each calibrated scale takes a long measurement: 50 readings in 10 blocks of 5. The median of each block is used, so single spikes are ignored, and the result is the average of the middle 6 block values. The first 5 blocks are also compared with the last 5 using the same **Stability limit** as calibration. If the load changed during the measurement, or the scale sent no readings, the measurement is retried after 5 minutes, up to 3 attempts. If every attempt is unstable, the last value is recorded and marked **U**. If no attempt got readings, that day is skipped.

Each scale gets one record per day. Consumption is the previous daily record's level minus the new level, converted with the beer density. The chart shows daily consumption as bars, and three lines per keg: the beer left in litres, the platform weight in kilograms, and the raw HX711 counts. Raw counts are in the millions, so they use the right-hand axis. Click any legend item to hide or show that line; a hidden line stays in the legend, dimmed, until it is clicked again.

- **Measure now** takes the same measurement immediately and saves a provisional record (light bar) for the day in progress, showing consumption so far. Pressing it again replaces that provisional record, and the next scheduled measurement replaces it with the final record. If today's scheduled measurement has already run, a manual measurement belongs to the next day.
- If the controller starts after the measurement time and today's record is missing, the measurement runs right away. Scheduled measurements wait until the clock is synchronized. A manual measurement without a synchronized clock is shown but not saved.
- A level rise of more than 2 kg since the previous record, or pressing **Keg changed** before the next record, marks the record as a keg change (**K**). That day's consumption is reported as zero and the new level becomes the reference. A level below the empty-keg threshold is recorded as no keg, also with zero consumption.

To measure how the scale reading drifts with temperature, the same card can run a sampling session. Set **Sample every (min)** (1 to 120, 2 by default) and **for (hours)** (1 to 72, 24 by default) and select **Start sampling**. The session needs the scale enabled, a synchronized clock and at least one active calibrated keg, and it samples every active calibrated keg, not only the selected one. A sample is a normal daily record flagged as a sample: it stores the level, the raw HX711 counts and the fridge temperature, but it never replaces or becomes the day's real record, and the daily chart skips it. The status text next to the buttons counts down as **Sampling, N min left**, and the session ends by itself at the end time; **Stop sampling** ends it early and keeps what was collected. Samples age out with the **History days** setting like every other record. Starting a session asks for confirmation and then deletes every sample of the previous session, so an export always holds exactly one experiment; daily records, settings and calibration are kept. The session itself lives in memory only: a reboot stops the sampling, but the samples already written stay in the log.

Scale settings are stored with the normal BrewPiLess settings. Daily records are stored separately in the filesystem as fixed-size records and kept for the **History days** setting (90 days by default, at most 365). The older pour-event history file is removed on the first start of this version. Saving keg or limit settings does not interrupt a running measurement. Changing the scale pins or turning the scale off stops it.

Each daily record also stores the raw HX711 counts and the fridge temperature at the measurement. The Scale page shows them in the chart, and **Export data** downloads the scale settings and every record as `scale_daily.json`, so the history can be inspected outside the controller. Sample records are included in the same file, one row per record as `[day, time, level, consumed, flags, scale, raw counts, temperature]` (the flags value 32 marks a sample record), with the level and consumption in grams and the temperature in °C. **Reset history** deletes every daily record, backup and temporary file, stops a running measurement, and restarts the consumption baseline from the current level; the next scheduled measurement for the day is skipped so a fresh record does not appear immediately. Calibration and keg settings are kept.

## Temperature Correction

The raw counts of a load cell drift with its temperature, so a keg that is not touched still shows a slowly changing weight while the fridge cycles. The controller can subtract that drift with a small polynomial per keg, where `t` is the fridge temperature in °C — always °C, also when the pages display °F — and the result is a shift in raw HX711 counts.

Measure the drift with a sampling session, then select **Export data** and open the downloaded `scale_daily.json` in BPLLogViewer, the standalone log viewer page. The viewer switches to scale mode and charts the keg weight and the raw counts. Scroll and zoom to the range to fit — the fit uses the records of the **selected keg** that have a raw count and a temperature within the current chart window; the dialog has a keg selector, defaulting to the keg with the most records in the window — then choose **Menu → Create Scale Temperature Correction**. The dialog fits a degree 2 or degree 3 polynomial of the raw counts against temperature, anchored so the correction is zero at the reference temperature; the reference defaults to the mean temperature of the data in view and can be edited; the formula is saved for the selected keg, so fit each keg separately. **Copy** puts the formula on the clipboard in exactly the text the Scale page accepts, and **Crop to** / **Save As** write the window as a smaller scale JSON file.

Back on the Scale page, paste the formula into **Correction formula** and select **Save formula**. The formula is stored for the keg chosen in the keg selector; **Clear** removes it, and the stored formula is rendered back into the box when the page loads. Text that is not a polynomial in `t` up to degree 3 — a comma as the decimal separator, an unknown term, a coefficient outside ±1,000,000, which the firmware would ignore anyway — is rejected with an error and nothing is saved; use a dot. The controller adds the stored correction to the raw counts before computing every weight it reports: the live weight, the daily measurement and with it the daily record, the keg level and the remaining litres, and the zero and factor calibration, so calibrating at any temperature produces constants as if taken at the reference temperature. The raw counts stored in the log stay uncorrected, so the drift can be fitted again after the coefficients change. Saving a formula shifts the reported level by a constant — the drift at the temperature the scale was last zeroed — so re-zero the empty platform (tare) after saving if the absolute level matters, and the next daily consumption entry absorbs the shift until then.
